Titolo: TheKnife – Tecnologie, Librerie e Strumenti
Versione: 1.0
Anno Accademico: 2024/2025

Introduzione
Questo documento descrive in dettaglio quali librerie, tecnologie e strumenti sono stati usati nello sviluppo di TheKnife, e le motivazioni alla base di tali scelte.

Tecnologie Principali

Linguaggio: Java

Versione: 17 o successiva (compilato e testato anche su Java 21)

Motivazione: fornisce portabilità, robustezza e supporto ampio di librerie standard. Ideale per CSV e GUI desktop

Libreria Standard Java (JDK)

Package principali: java.io, java.util, java.awt, javax.swing

Utilizzati per gestione file, collezioni, GUI

Swing

Scopo: interfaccia grafica desktop (JFrame, JPanel, JDialog...)

Layout: FlowLayout, GridLayout, BorderLayout, CardLayout

Motivazione: incluso nel JDK, stabile, ottimo per GUI semplici senza dipendenze esterne

Librerie Esterne

NimbusLookAndFeel

Incluso nel JDK (Java 6u10 in poi)

Scopo: fornire un aspetto grafico più moderno rispetto al tema Metal

Nessuna libreria di terze parti aggiuntiva utilizzata

Strumenti di Sviluppo

IDE: Visual Studio Code (con Extension Pack for Java), Eclipse, o IntelliJ IDEA

Compilazione (CLI):

javac -d bin src/theknife/*.java src/theknife/gui/*.java src/theknife/gui/panels/*.java

Creazione JAR:

jar cfe TheKnife.jar theknife.gui.MainApp -C bin .

Versionamento (opzionale):

Git (consigliato)

Hosting su GitHub o GitLab per collaborazione e backup

Gestione File CSV

Approccio:

Lettura: carica tutto in memoria con BufferedReader

Scrittura: sovrascrive l’intero file con PrintWriter

Pro: semplice, didattico, adatto a piccoli dataset

Contro: non supporta concorrenza; rischio di conflitti se usato in contesti multiutente

Eventuali Dipendenze e Compatibilità

Compatibilità OS: testato su Windows 10/11 e Ubuntu 22.04

Versioni Java compatibili: 17, 19, 21

Dipendenze esterne: nessuna oltre al JDK

Conclusioni
TheKnife è costruito con tecnologie standard e consolidate. L’approccio file-based e GUI desktop è perfetto per un progetto didattico come il Laboratorio Interdisciplinare. L’uso di Java puro e l’assenza di dipendenze esterne garantiscono massima compatibilità e semplicità. In futuro, è possibile estendere il progetto con database, sicurezza avanzata, o architettura client-server.
