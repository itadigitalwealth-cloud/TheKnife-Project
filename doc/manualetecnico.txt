Titolo: TheKnife – Manuale Tecnico
Versione: 1.0
Anno Accademico: 2024/2025

1. Scopo del Documento
Questo Manuale Tecnico fornisce una vista approfondita sull’architettura software e sui meccanismi di funzionamento di TheKnife, con particolare attenzione a:
- Struttura dei package
- Classi principali (modelli, logica di business, interfaccia)
- Metodologie di lettura/scrittura su file (CSV)
- Gestione degli utenti e delle recensioni
- Possibili estensioni future

2. Architettura Software
2.1 Suddivisione in Package
- `theknife`: Modelli e logica principale
  - Classi: `Ristorante`, `Utente`, `Recensione`, `GestoreFile`
- `theknife.gui`: Interfaccia grafica generale
  - Classi: `MainApp`, `FancyFrame`, `LoginDialog`, `RegisterDialog`, `GradientPanel`
- `theknife.gui.panels`: Pannelli specializzati
  - `HomePanel`, `SearchPanel`, `RistorantiPanel`, `RecensioniPanel`, `PreferitiPanel`, `RestaurantDetailPanel`

2.2 Flusso Principale
- `MainApp`: Imposta LookAndFeel e avvia `FancyFrame`
- `FancyFrame`: Contiene la barra superiore, menù laterale e centro con `CardLayout`
- I vari pulsanti del menu attivano i pannelli tramite `showCard(...)`
- Alcune funzionalità sono limitate se non si è loggati (`utenteCorrente == null`)

2.3 Interazione con i File CSV
- `utenti.csv`: gestione login, registrazione
- `ristoranti.csv`: aggiunta e visualizzazione ristoranti
- `recensioni.csv`: gestione recensioni e risposte
- `preferiti.csv`: gestione lista preferiti del cliente
- `cercaRistoranti(...)` filtra i dati in memoria da `ristoranti.csv`

2.4 Vantaggi
- Separazione interfaccia/logica/IO
- Modularità per ogni componente
- Scalabilità: possibile aggiunta di nuovi ruoli o funzionalità

3. Strutture Dati
3.1 Ristorante
```java
public class Ristorante {
    private String nome, citta, indirizzo, tipoCucina, proprietario;
    private double latitudine, longitudine, fasciaPrezzo;
    private boolean delivery, prenotazione;
}
```
Caricato da `ristoranti.csv`

3.2 Utente
```java
public class Utente {
    private String nome, cognome, username, passwordCifrata;
    private String dataNascita, domicilio, ruolo;
}
```
Usato per login e registrazione da `utenti.csv`

3.3 Recensione
```java
public class Recensione {
    private String idRistorante, username, testo, risposta;
    private int stelle;
}
```
Salvato in `recensioni.csv`, supporta risposte del ristoratore

3.4 File CSV
Ogni file ha intestazione e dati separati da `;`. Il `GestoreFile` gestisce lettura/scrittura.

4. Gestione File in GestoreFile
- `caricaXxx(String file)`: legge i CSV e costruisce gli oggetti
- `salvaXxx(List, String file)`: salva oggetti nel formato CSV
- `aggiungiXxx(...)`: pattern "carica → modifica lista → salva"
- `modificaRecensione`, `eliminaRecensione`, `rimuoviPreferito`, ecc. aggiornano le righe in base a username/ristorante

4.1 Metodo cercaRistoranti
Filtra i ristoranti in base a:
- nomeParziale
- citta
- tipoCucina
- maxPrezzo
- delivery
- prenotazione
Restituisce `List<Ristorante>` filtrata

5. Interfaccia Grafica (GUI)
5.1 FancyFrame
- Usa `CardLayout`
- Barra in alto (logo + titolo)
- Menu laterale con voci dinamiche (login/logout)

5.2 Pannelli
- `HomePanel`: benvenuto
- `SearchPanel`: filtra ristoranti + link al `RestaurantDetailPanel`
- `RistorantiPanel`: solo per ristoratore, aggiunta + elenco ristoranti propri
- `RecensioniPanel`: gestione recensioni (inserisci/modifica/rimuovi/rispondi)
- `PreferitiPanel`: solo cliente, aggiunta/rimozione preferiti

5.3 Dialoghi
- `LoginDialog`: login, con validazione credenziali e ruolo
- `RegisterDialog`: inserimento nuovo utente, verifica duplicati, salvataggio

6. Sicurezza e Limitazioni
- Password salvate in chiaro (da cifrare con hash+salt in estensioni future)
- Nessun controllo concorrente sui file
- Proprietà ristoranti non strettamente verificata (presente come campo, ma senza ACL)
- Sistema non distribuito né client-server (solo GUI desktop)

7. Estensioni Future
- Hashing password e miglior sicurezza login
- Uso di database relazionale (es. SQLite, MySQL)
- Controllo ACL per ristoranti (verifica utente == proprietario)
- Interfaccia web o versione mobile
- Gestione utenti "admin" con permessi avanzati

8. Conclusione
La struttura modulare, i package ben separati e l’approccio file-based rendono TheKnife un progetto didattico completo e facilmente estendibile. La documentazione e la gestione via GUI forniscono un’esperienza utente coerente e chiara per entrambi i ruoli: cliente e ristoratore.
